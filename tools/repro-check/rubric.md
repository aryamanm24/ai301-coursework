# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | The repro report's environment record (the `Environment:` line or equivalent) read against the issue's stated version/OS and the repo-facts bug-template asks. | Pass if the report names the tool/version tested AND the OS/platform. If that version differs from the issue's target (or from "latest"/"main" the thread confirmed on), the report must name the delta. Fail if either the version or the OS is missing, or if a different version is used with no mention of the difference. | required |
| steps-followable | The repro report's steps, commands, and any named files/configs, read as a stranger starting from a fresh clone or a stated starting state. | Pass if a stranger could re-run the attempt: a starting state plus the actual commands (or exact clicks) that trigger the check. Fail if there are no steps, if a required command is only described ("set up the project"), if a critical flag/driver/config the issue depends on is omitted, or if the repro lives in a private/unshared repo or config a stranger cannot obtain. | required |
| behavior-matches | The report's output excerpts, logs, or other artifacts, read against the issue body's described actual behavior (error class, exit code, missing field, panic, blank pane, etc.). | Pass if the shown artifact is the issue's behavior, or if the report is an evidenced cannot-reproduce: it shows what actually happened and does not claim the issue's symptom. Fail if there is no artifact, if the artifact only shows that the tool runs, or if the artifact is an adjacent failure (arg-validation, compile error, garbled-but-alive output, old-version error) narrated as the reported bug. | required |
| honest-outcome | The report's stated result ("reproduced" / "could not reproduce" / "root cause") read against the artifacts it actually shows. | Pass if the sentence that states the outcome matches the artifact: reproduced only when the issue's behavior is shown; cannot-reproduce when the shown run did not trigger it; a cause only when the artifact supports it. Fail if the write-up is more confident than the evidence (crash claimed over an exit-1 validation error, "verified this race" with no transcript, "expected" stated backwards from what was shown). An honest cannot-reproduce with a shown run is a pass. | required |
| claim-specific | The candidate claim comment, read against the issue title/body. | Pass if the claim names this issue's specific behavior or trigger (not just the number) and states a next step that is an investigation or a repro report, not a guaranteed fix or a date. Fail on +1/me-too with no intent, assign-me boilerplate, "amazing project" with no named behavior, or a promise to fix by a deadline. | required |
| ai-disclosure | Repo-facts `contribution policy` plus the claim comment and repro report. | Pass if the policy does not require disclosing AI usage, or if it does and at least one of the comments names the AI tool or that AI assistance was used. Fail only when the policy requires disclosure (for example "must be disclosed", "all AI usage … must be disclosed") and neither comment discloses. Course packages are AI-assisted work. Conditions such as "understand the work" or "assistive AI allowed" without a disclose-ask are not a fail. | required |

## Verdict rule

Accept if and only if every required check is pass. Preferred checks never change the verdict. Treat unclear on a required check as fail: proof you cannot verify is not ready to post.
